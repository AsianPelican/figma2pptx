# figma2pptx Figma plugin

Select frames in Figma Desktop on the client Mac, click Export, and download a native editable PPTX plus PDF. The plugin never receives the Figma REST token and never changes the Figma file. Conversion, font resolution, caching, and PowerPoint run only on a dedicated bridge Mac.

## One-time bridge-Mac setup

The bridge Mac needs the repository, the required installed fonts, Bun, ImageMagick, Poppler, fontconfig, and a signed-in Microsoft PowerPoint. Keep code and runtime state separate under `~/Projects`:

```text
figma2pptx/                 clean public-repository clone; code only
figma2pptx-runtime/
  config/                   owner-only token environment and bridge secret
  cache/                    Figma REST responses and rendered assets
  jobs/                     durable job index plus date/deck requests, PPTX, PDF, and reports
  logs/                     launchd stdout and stderr
  launcher/                 stable signed local app identity for macOS Automation
```

Create `figma2pptx-runtime/config/bridge.env` relative to `~/Projects`:

```text
FIGMA_TOKEN=your-personal-access-token
FIGMA2PPTX_BRIDGE_HOST=127.0.0.1
```

Protect it, install dependencies, build, and install/start the user launch agent:

```sh
cd ~/Projects
mkdir -p figma2pptx-runtime/{config,cache,jobs,logs}
chmod 600 figma2pptx-runtime/config/bridge.env
cd figma2pptx
bun install --frozen-lockfile
cd plugin
bun install --frozen-lockfile
bun run build
bun run bridge:install
```

`bun run bridge:install` is the one-command persistent start. It creates a per-install 64-character secret in `figma2pptx-runtime/config/bridge-secret`, keeps both credential files owner-only, starts `local.figma2pptx.bridge` in the current GUI launchd domain, and adds a private-network HTTPS endpoint without replacing existing services. The launch agent writes only to the sibling runtime tree; each conversion runs as an isolated child of the same deterministic library. For foreground diagnosis, `bun run bridge` uses the same owner-only environment file.

On first install, the service builds a tiny local launcher app under the runtime tree and signs it with an explicit stable designated requirement. The launch agent keeps that app running while it starts Bun as a child, giving macOS Automation one identity even when Bun is upgraded. The installer preserves the existing launcher and never re-signs it while that requirement remains valid, so an accepted PowerPoint grant survives routine reinstalls.

The Bun bridge listens only on `127.0.0.1:38456`. Tailscale Serve terminates TLS and exposes that listener only inside the private network on HTTPS port `38458`; neither layer binds a LAN or public interface. Preflight responses explicitly allow browser Private Network Access.

## Generate your own bridge secret

No credentials are included in the repository or built plugin. `bun run bridge:install` (or the foreground bridge on first start) uses `randomBytes(32)` to create a fresh 64-character hex secret in the sibling runtime config folder with mode `0600`. Every installation generates its own value; keep it outside the repository and never paste it into a URL, commit, or issue. Pair only with the secret generated by your bridge.

## Client-Mac setup

Set the private bridge origin, then build the development plugin:

```sh
cd plugin
bun install --frozen-lockfile
FIGMA2PPTX_BRIDGE_ORIGIN='https://bridge-host.example:38458' bun run build
```

Replace `bridge-host.example` with the bridge Mac's fully qualified private-network hostname. Figma rejects dotless hostnames. The build creates the complete importable development plugin under `plugin/local/`: a real `manifest.json` plus its `dist/` files. The folder is ignored by Git because it contains the configured private bridge origin. If the repository is in a hidden worktree, copy the complete `local/` folder to a visible stable location such as `~/Desktop/figma2pptx-plugin/` before importing it; keep `manifest.json` and `dist/` together.

Copy the bridge secret without displaying it. The CLI reads this file; the final command puts the same secret on the clipboard for one-time plugin pairing:

```sh
mkdir -p ~/.config/figma2pptx
scp <bridge-ssh-host>:Projects/figma2pptx-runtime/config/bridge-secret ~/.config/figma2pptx/bridge-secret
chmod 600 ~/.config/figma2pptx/bridge-secret
ssh <bridge-ssh-host> 'dd if="$HOME/Projects/figma2pptx-runtime/config/bridge-secret" status=none' | pbcopy
```

Both Macs must remain connected to the private network. The client Mac needs no Figma token and performs no conversion or PowerPoint work.

## Load and export in Figma Desktop

1. Open Figma Desktop on the client Mac.
2. Choose **Plugins > Development > Import plugin from manifest…**.
3. Select the generated `plugin/local/manifest.json` (or the copied visible folder's `manifest.json`).
4. Open the design file and select one or more top-level frames.
5. Choose **Plugins > Development > figma2pptx Export**.
6. Paste the clipboard secret and click **Connect** once. Figma stores it in plugin-local `clientStorage`; later opens connect automatically.
7. Confirm the frame names and click **Export selected frames**.
8. Watch stage, slide, and elapsed-time progress. If the stream drops or the plugin is reopened, it reattaches to the durable job by ID until conversion finishes.
9. When the export finishes, click **Download** for PowerPoint and PDF. Each download is authenticated and SHA-256 verified before the browser saves it to the client Mac's Downloads folder.

Transient network failures retry automatically with capped backoff and show **Reconnecting…**. The secret field is hidden after pairing and returns only when no secret is stored or the bridge responds with `401`.

PowerPoint on the bridge Mac must be signed in, free of open presentations, and free of dialogs. If it is busy, unavailable, or waiting for macOS Automation permission, the bridge reports the exact reason in the plugin; it never closes, saves, or changes an unrelated deck.

PowerPoint files never embed fonts. The bridge rejects requests that try to enable embedding, while still using the installed fonts to lay out editable text.

## One-time macOS permission checklist

Complete these once on the bridge Mac. The stable launcher identity means routine bridge updates do not require repeating them:

1. Open **System Settings > Privacy & Security > Automation** and allow **Figma2Pptx Bridge** to control **Microsoft PowerPoint**.
2. Open **System Settings > Privacy & Security > Full Disk Access** and enable `figma2pptx-runtime/launcher/Figma2Pptx Bridge.app` under `~/Projects`.
3. Launch PowerPoint once, sign in, finish or dismiss onboarding/update/repair dialogs, then close every presentation while leaving the application available.

Validate the complete grant set and a real one-slide PowerPoint export from the service identity:

```sh
cd ~/Projects/figma2pptx/plugin
bun run doctor
```

Doctor sends its hard permission checks through the stable launcher—the same context production exports use. It fails with the exact missing grant when the launcher cannot read protected app data, when Automation is denied, when PowerPoint has a presentation or dialog open, or when a bounded headless export cannot finish without a prompt. SSH-context access is informational only because Tailscale SSH does not run through Apple's Remote Login service. Its synthetic PPTX/PDF evidence stays under `figma2pptx-runtime/jobs/doctor/`.

The converter copies every deck PowerPoint opens, and every PDF PowerPoint writes, through `~/Library/Containers/com.microsoft.Powerpoint/Data/tmp/figma2pptx-*`. It never asks PowerPoint to open a runtime-job or `/tmp` path. If the PowerPoint container is unavailable, conversion stops and names the Full Disk Access grant instead of falling back to a path that would raise **Grant File Access**.

## Client-Mac CLI

The plugin package includes an optional thin remote client for terminal diagnosis:

```sh
cd plugin
bun run remote '<figma-url-or-fileKey>' '12:34' '56:78' --pdf -o "$HOME/Downloads/deck.pptx"
```

Set `FIGMA2PPTX_BRIDGE_ORIGIN` to the same configured origin. The client sends only the validated job request and bearer header to the bridge, streams the same progress, downloads the outputs, verifies their sizes and SHA-256 digests, and moves them into the requested local paths. It never loads the converter or calls PowerPoint locally.

## Development

```sh
bun test
bun run typecheck
bun run build
bun run validate-manifest
```

The tracked manifest and UI contain only a non-routable placeholder. If imported accidentally, the source UI disables pairing and directs the operator to the configured build without attempting a fetch. `bun run build` creates an ignored, self-contained `local/` folder that permits exactly the configured origin. Export and download calls use the bearer secret only in the `Authorization` header. The owner-only durable job index lets status checks and authenticated downloads survive service restarts; a dropped progress stream does not cancel the converter. This is a local development plugin; do not publish it to the Figma Community.

Refresh the visible Desktop bundle only through the guarded command:

```sh
FIGMA2PPTX_BRIDGE_ORIGIN='https://<live-private-host>:38458' bun run desktop:refresh
```

It rejects placeholder/test origins, requires the owner-only bridge secret (default `~/.config/figma2pptx/bridge-secret`), requires an authenticated `200` from the live health endpoint, checks the generated manifest and UI origins, and verifies all three copied files. Manifest tests use isolated temporary fixtures and never mutate `plugin/local/`.
